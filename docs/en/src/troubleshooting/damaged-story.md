# If a Story Appears Damaged

If passages are missing, text is garbled, or the graph looks wrong, stop editing
the affected story. Capture the error message and preserve the current
[browser storage](local-storage.md) or complete
[desktop project folder](../story-library/location.md) before restarting or
trying a repair. Restarting is not a general-purpose story repair procedure.

Check whether the source text is damaged or only the preview behaves
unexpectedly. A missing asset or a changed story format can affect Play/Test
without destroying passage text. Keep the recorded story format and version
when testing a recovered copy.

If Twine RS shows an external-change or interrupted-operation recovery prompt,
read which version each choice will keep. Preserve the current data and the
available backup before choosing an option that replaces or discards either
version. Do not remove recovery records manually to dismiss the prompt.

Test a known-good export or project backup in a separate browser profile or
isolated desktop library. Follow [missing-story recovery](lost-story.md) and
[desktop backup restoration](backups.md) as appropriate. Confirm passage text,
scripts, stylesheet, start passage, format, and assets before making the recovered
copy your working version. Keep the damaged original until recovery is complete.

If you cannot recover the story, report the exact Twine RS version, operating
system or browser, steps leading to the problem, and a redacted error message
through [Twine RS support](https://github.com/twine-rs-labs/twine.rs/blob/main/SUPPORT.md).
Share a minimal example only if it is safe to publish; full projects and browser
storage snapshots can contain private story content.
